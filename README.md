# LFOwn

A memecoin launchpad on Solana where the other side of every pool is a MetaDAO
ownership coin — an asset with a redeemable treasury behind it — rather than SOL.
One Cloudflare Worker serves the landing page, the launch and coins apps, a small
API and three crons. Launch and trade transactions are built in the browser against
Meteora's Dynamic Bonding Curve and signed by the visitor's own wallet; nothing but
the signed bytes reaches the server.

```
public/
  index.html            the landing page (CSS + markup inline, ships no bundle)
  launch/index.html     the launch app shell
  coins/index.html      the coins app shell
  app/                  the bundled app — generated by `npm run build`, not committed
  assets/               logos, banner, the shared stylesheet
src/
  worker.mjs            the Worker: routing, the API, the crons, the keeper
  lib/                  shared by the Worker and the scripts: config, registry, fees, graduation, chart, telegram
  app/                  the browser app: launch flow, coins and trading, wallet, funding, vanity search
  partials/header.html  the one header every page carries
scripts/                operator scripts: open configs, claim fees, graduate, test
wrangler.jsonc          Cloudflare config: assets, KV, R2, crons, rate limits
```

## Run it locally

    npm install
    echo 'HELIUS_RPC=https://mainnet.helius-rpc.com/?api-key=…' > .dev.vars
    npm run dev                 # builds, then `wrangler dev` on http://localhost:8787

**The dev server talks to production data.** `wrangler.jsonc` binds the KV
namespace and the R2 bucket with `remote: true`, so `wrangler dev` reads and writes
the same catalogue, launches and uploads as the live site. That is deliberate — the
configs and the launches only exist there — but it means an image uploaded from a
dev server lands in the real bucket. Point the bindings at a preview namespace and
bucket if you want a sandbox.

`.claude/launch.json` starts the same dev server on port 8794 for Claude Code's
browser preview.

## Deploy

    npm run deploy

Before the first deploy:

    npx wrangler kv namespace create REGISTRY     # paste the id into wrangler.jsonc
    npx wrangler secret put HELIUS_RPC
    npx wrangler secret put FEE_COLLECTOR_KEY     # optional — see "Where the claimer lives"
    npx wrangler secret put TELEGRAM_BOT_TOKEN    # optional, with TELEGRAM_CHAT_ID
    npx wrangler secret put TELEGRAM_CHAT_ID

Then add a **rate limiting rule on `/api/*`** in the zone's WAF (Security → WAF →
Rate limiting rules; one rule is included on the free plan). The Worker enforces
its own per-address ceilings — see *Security* — and the zone rule is the layer
above them: without it, a flood spread across many addresses is still a flood.

The site lands on `https://lfown.<your-subdomain>.workers.dev` as well as the custom
domains in `wrangler.jsonc`. Consider disabling the `workers.dev` route once the
domain works: a perfect copy of the site on a second hostname is a gift to phishers.

## The deployer key

`npm run keygen` writes `.keys/lfown-deployer.json` (gitignored, mode 600) and the
launch scripts pick it up automatically. It only ever pays account rent: fees are
claimed by `FEES.recipient`, which this key has no authority over, and the DBC
configs it creates are not updatable. Losing it costs the rent already spent and
nothing else — but back it up anyway, and keep it off any machine you would not
trust with a hot wallet.

## Opening a coin for launches

One DBC config per ownership coin per tier, created once and reused by every
creator — the fee claimer and the 50/50 split are baked in, so a launch is a single
`createPool` from the browser.

A config is immutable: its fee rate, its fee claimer and its graduation threshold
cannot be changed afterwards. Changing any of them means opening new configs and
republishing them to KV; coins already launched keep trading on the old ones. The
launch screen therefore reads the fee back from KV, so it quotes what the config
will really charge rather than what `FEES` currently says.

    node scripts/create-config.mjs all starter                # dry run over every coin
    LFOWN_ARM=yes node scripts/create-config.mjs all starter  # sends, ~0.0075 SOL each

Pass a single mint instead of `all` to open one coin. Coins already open on that
tier are skipped, and each config is written to KV as soon as it confirms.

The graduation threshold lives inside the config, so it cannot vary per launch —
a creator picks one of the tiers in `src/lib/config.mjs` ($5k / $15k / $50k,
converted to backing coins at the price on the day the tier was opened). Open the
tiers you want to offer; publishing to KV is part of the run.

Image uploads use the `lfown-images` R2 bucket, bound as `IMAGES`.

Until a coin has a config, the launch page says so instead of failing at signature.

## Pages

`/` landing · `/launch` the four-step launch flow · `/coins` the launched coins,
`/coins/:mint` one coin with a buy/sell form. Trading before graduation is priced
by the SDK's curve maths against live pool state — the pool is on no DEX yet, so
nothing else can quote it.

`PUBLIC_ORIGIN` is set in `wrangler.jsonc` to the public domain. Token metadata
URIs are written on-chain and never change: without it, a launch made from a dev
server carries a dead link forever.

## Security

- **Chain data is hostile.** A token's name, symbol and image are written by whoever
  launched it. Everything from chain goes through `esc()` / `safeUrl()` in
  `src/app/escape.js` before touching the DOM; a coin named `<img onerror=…>` once
  ran script on this origin, which is the origin where transactions are built.
- **The collector key is hot, and it is worth more than one sweep's fees.**
  `FEE_COLLECTOR_KEY` is the fee claimer written into every config, which is
  immutable, and after a graduation it holds LFOwn's locked position in the coin's
  DAMM v2 pool, which is a transferable NFT. Whoever takes the key takes the
  partner's share of every curve opened so far — retiring the configs stops new
  launches, not the fees of coins already on them — and the graduated income of
  every coin already graduated, for good. It cannot touch the treasury: claims land
  there directly and receiving needs no signature. Keep as little SOL on it as the
  keeper needs, and read *Where the claimer lives* below.
- **Every route that costs something is rate limited per address in the Worker**
  (`ratelimits` in `wrangler.jsonc`): the RPC proxy on its own ceiling; the chart,
  launch, exit, graduate, image and metadata routes on a shared one. A JSON-RPC
  batch is at most ten calls and 64 KB. An exit quote prices at most three sizes. A
  chart is only built for a pool on one of our configs. A mint with no pool, or a
  pool on somebody else's config, is remembered for five minutes at the edge rather
  than scanned again. These stop one script, not a botnet: the WAF rule is the fence.
- **Nothing public can drop a cache.** Publishing metadata used to delete the
  launches list so a new coin would show up sooner, and anyone could post there.
  Now the graduation endpoint adds the coin to the list once its pool is confirmed on
  chain, and a list or fee report that has expired is rebuilt by one request while
  the others wait for that copy.
- **`/api/rpc`, `/api/image`, `/api/metadata` and `/api/graduate` reject cross-site
  origins.** A speed bump, not a fence: a script can forge `Origin`. The rate limits
  are the control.
- **Uploads pin their content type** from an allowlist and are served `nosniff`, so a
  file stored through `/api/image` cannot come back as HTML.
- **A creator's links are http(s) or nothing**, dropped at `/api/metadata` before
  they are stored, and a metadata document fetched from elsewhere is given five
  seconds and 64 KB.
- `npm audit` reports 17 advisories, all transitive. Those under `@solana/web3.js`
  and the Meteora SDKs are upstream and unfixable here — `npm audit fix --force`
  would downgrade web3.js to 0.0.3 — and only one reaches the browser bundle:
  `bigint-buffer`, whose overflow is reachable through malformed account data read
  by the SDK, which is a crashed tab at worst. Those under `wrangler` (`sharp`,
  `miniflare`) are development tooling only and clear with `npm update wrangler`.
- Found something? See `SECURITY.md`.

## Wallets

The last wallet someone connected is remembered by name, and a reload asks it to
reconnect with `{ silent: true }` — the wallet answers only if it already trusts the
site, so a refresh costs neither a click nor a popup. Disconnecting forgets it.

Discovery is the Wallet Standard handshake plus the older injected globals
(Phantom, Solflare, Backpack, Glow, Coinbase, Trust), no adapter library. Wallets
that register after page load repaint the buttons. With one wallet installed the
connect button connects it; with several it opens a picker.

## The header

`src/partials/header.html` is injected into all three pages by
`scripts/build-html.mjs`, which `npm run build` runs first. The pages once carried
their own copies and drifted into three different navigations; now changing one
means changing the partial. Only the right-hand action differs — a call to action
on the landing, which ships no bundle, and the wallet button on the app pages.

## Fees

`FEES` in `src/lib/config.mjs` sets the rate and the recipient; both are written
into each config when it is opened, and cannot be changed afterwards.

Meteora keeps 20% of every trading fee before the rest is split, so 2.5% per trade
lands as 1% creator, 1% LFOwn, 0.5% Meteora. `feeBreakdown()` does that arithmetic
and the launch screen shows all three.

Fees are pull, not push: each trade parks the partner's share inside the pool
account, in the ownership coin. `node scripts/claim-fees.mjs` reports what has
accrued across every pool; `LFOWN_ARM=yes` claims it.

The program accepts exactly one signer for a claim — the fee claimer — but it needs
no SOL: the network fee and the destination account's rent are paid by a co-signer,
which is the deployer here. So a claim needs the claimer's authority, not its
balance. `LFOWN_CLAIMER_KEYPAIR=` points at that key; `--unsigned` prints
payer-signed transactions for a wallet or multisig to countersign instead.

The creator's half works the same way but only their signature moves it, so it is
claimed from the coin's own page rather than a script.

### Seeing it all

`GET /api/fees` reports, per coin, what the curve earned and what the graduated
position has earned since, split between creator, LFOwn and Meteora. Nothing is
indexed: a curve records its lifetime fees and a position records what it has
claimed, so adding the unclaimed remainder reconstructs the history from two account
reads. `/coins` shows the totals and a per-coin line.

One gap to know about: Meteora's cut of the **graduated** pool is not attributed —
the figure under "To Meteora" is the curve's protocol fee only, so the real split
after graduation is slightly less favourable than shown.

### After graduation

The curve's fee counters stop at migration. From then on the coin trades in a DAMM v2
pool whose liquidity is two permanently locked positions — one LFOwn's, one the
creator's — and locked liquidity still earns, **in both tokens** rather than only the
quote. Those fees belong to a different program and need `claim_position_fee`.

`src/lib/lp-fees.mjs` reads them (`getUnClaimLpFee`, because the `feeAPending` field
on a position is a checkpoint rather than a balance) and builds the claim. The hourly
sweep, `scripts/claim-fees.mjs` and the coin page all cover both phases.

### The hourly sweep

A cron at the top of every hour claims the partner's share into `FEES.treasury`,
skipping anything under $1 — a claim costs more than dust is worth. It runs only
when `FEE_COLLECTOR_KEY` holds the config's fee claimer, and logs that it skipped
otherwise. `FEES.recipient` (who signs) and `FEES.treasury` (where money lands) are
separate on purpose: claims never pass through the collector, so the treasury is
out of the key's reach whatever happens to it.

### Where the claimer lives

Today the Worker holds the claimer, because the hourly sweep needs its signature —
and that makes it a hot key with the reach described under *Security*. The safer
arrangement is two keys: a keeper in the Worker that only pays for migrations and
holds a few tenths of a SOL, and the claimer on a machine that is not a server, used
by `scripts/claim-fees.mjs` when there is something worth claiming. Fees wait in
the pools between claims, where only the claimer can move them, and the position
NFTs of graduated coins are minted to the claimer's address — so with the claimer
cold, they are cold too. The price is that claiming becomes a chore rather than a
cron.

Moving the existing key out of the Worker changes nothing on chain; the address
stays the claimer. Only if the key is *replaced* do new configs have to be opened,
and coins on the old ones keep paying the old claimer.

## Reopening a tier

`node scripts/close-configs.mjs` lists the published config pointers, `LFOWN_ARM=yes`
retires them so `create-config.mjs` will open fresh ones. Retired pointers move to
`retired:` and `/api/launches` still reads them, so coins launched on an old config
stay listed — they keep trading on chain either way. `--forget` drops them instead,
which unlists their coins; that is for clearing test launches, not for real ones.

## Build

`public/app/` is generated — `npm run build` (esbuild), and `npm run deploy` builds
before publishing. The catalogue screen stays small; the web3/DBC bundle only loads
when someone actually launches or trades.

## Graduation

A filled curve does not migrate itself. `migration_damm_v2` takes a payer and two
throwaway position-NFT keypairs and **no authority at all**, so anyone may crank it —
which means nobody has to, and a launch would otherwise sit at 100% with its
liquidity trapped in the bonding curve.

Three things crank it. The trade that fills a curve, and the launch whose dev buy
fills it, call `POST /api/graduate` — after their transaction has confirmed — and
the keeper reads the pool from chain, checks that it sits on one of our configs and
that the reserve really has reached the threshold, and only then spends. A
minute-by-minute cron reads every live pool in one batched call for fills made
elsewhere, since Jupiter routes into these pools. And the ten-minute catalogue job
graduates at most one ready pool per run as the backstop. `node scripts/graduate.mjs`
does the same by hand (`LFOWN_ARM=yes` to send).

The graduation endpoint is also how a new coin reaches the cached list without a
rebuild: a pool it has just verified is added to the list, and a pool it has just
migrated is marked so.

## Tests

    npm test

Runs against devnet with a stand-in quote mint — a plain 6-decimal SPL token,
mechanically identical to every ownership coin checked on chain. It covers the fee
arithmetic, then config → launch → buy → sell → partial fill → graduation, asserting
at each step. The on-chain half skips itself with the address to fund when the devnet
wallet is empty.

`node scripts/canary-mainnet.mjs` is the same flow against a real ownership coin. It
is a dry run unless `LFOWN_ARM=yes` is set, and it spends real funds when armed.

    npm run test:worker

Exercises the Worker's abuse limits offline — a fake RPC that counts program scans,
KV and R2 in memory — so it runs anywhere and touches nothing: the JSON-RPC caps,
the exit-size cap, the rebuild locks, the metadata route leaving the cache alone,
and the misses remembered for chart, graduate and launch.

## API

Served by the Worker (`src/worker.mjs`). The Helius key stays server-side.

| Route | What |
|---|---|
| `GET /api/quote-assets` | live MetaDAO DAOs from `market-api.metadao.fi`, with their real treasury (`treasury_usdc_aum`), price and liquidity, plus icons and holders from Jupiter. A DAO whose treasury is under `MIN_TREASURY_USD` ($10) is dropped; nothing is filtered out for being thin. |
| `GET /api/exit/:mint?usd=1000,5000` | what a holder really receives selling that size into USDC right now, and through which venues. At most three sizes. |
| `GET /api/config/:mint` | the DBC config per tier for that coin, `null` for tiers LFOwn has not opened |
| `GET /api/launches` | every coin launched on an LFOwn config, read from chain with its on-chain name, symbol and uri. Served from KV, rebuilt behind the response once it is a quarter of an hour old. |
| `GET /api/launch/:mint` | one coin, from the list when it is known and from chain when it is not. A miss is kept at the edge for five minutes. |
| `GET /api/chart/:mint` | the coin's price history, rebuilt from its own trades. Only for pools on our configs. |
| `GET /api/fees` | what every coin has earned and for whom |
| `POST /api/image` | token image upload to R2, served back from `/i/:key` (CORS-open, wallets read it) |
| `POST /api/metadata` | writes the Metaplex JSON the token's on-chain `uri` points at |
| `POST /api/graduate` | asks the keeper to migrate a curve that has filled; every claim is checked against chain before a lamport is spent |
| `POST /api/rpc` | allowlisted read/send proxy to Helius, so the key never reaches the browser. Ten calls per request at most. |

A cron every 10 minutes rebuilds the catalogue into KV. Exit costs are priced on
demand and cached 60s, which keeps each request well under the subrequest ceiling.

## Themes

Light by default, dark on request. The theme resolves before first paint from an
inline script in `<head>`: saved choice (`localStorage['lfown-theme']`) wins,
otherwise the OS `prefers-color-scheme`. The sun/moon button in the header flips
it and stores the choice. All colours come from CSS variables on `:root`, so a
palette change is a one-block edit.

## Notes

- Fonts: Bricolage Grotesque (display), Newsreader (body), Martian Mono (labels),
  Permanent Marker (brush fallback) — from Google Fonts.
- The X post is a real embed (`platform.twitter.com/widgets.js`); if the script is
  blocked it degrades to a styled quote with a link.
- Scroll reveals are pure CSS (`animation-timeline: view()`): unsupported browsers
  just show the content, and `prefers-reduced-motion` is respected.
- Colours live in the `:root` / `:root[data-theme="dark"]` blocks at the top of
  `public/assets/lfown.css`.
